# Inquiries, settings and registered validators

Implementation for [issue 98](https://github.com/bc-solutions-coder/bcordes/issues/98), based on `d0e5722`, implemented in `ed10255`. [dispositions.tsv](dispositions.tsv) maps all 104 original cases to their replacement behavior. The 36 accepted structural or duplicate declarations were removed or consolidated after the replacements passed. The copied-schema and status-map test files are gone.

Inquiry server tests execute the actual registered Zod validators and handlers through a thin framework adapter, then inspect real SDK requests. They cover all supported enum choices, invalid UUIDs, length limits, explicit inbound and outbound status mappings, ownership, internal-note privacy, expired sessions, and signed-in versus service-client submissions. The fixture supplies distinct authorization headers; actual credential propagation remains covered by the auth and browser boundaries from earlier slices. This adapter proves validation and handler behavior, not framework HTTP transport.

Notification validation covers UUIDs, URL syntax and endpoint/key/auth length boundaries. Valid authenticated push inputs reach the current unavailable contract with no outbound push request. HTTP remains a valid URL input; these tests do not invent an HTTPS-only policy or functioning push delivery.

Dashboard tests load the real nested routes, auth middleware, SDK and server functions against a controlled request boundary. Opposing roles and permissions expose role-only authorization mistakes. Distinct inquiry UUIDs select distinct details and comments. Status changes preserve the actual PATCH payload and refresh the row without navigating. Customer labels retain all four capitalized statuses; staff controls display their current lowercase values. Detail status formatting, public and internal comments, pending controls, trimmed payloads, reset, draft retention and retry are observed through rendered controls.

The real router handles a failed refresh by displaying its error screen. Recovery uses its public invalidate operation and restores an enabled Refresh button. No process rejection listeners are removed. Failed status writes show the real error toast and preserve the saved row; failed detail comments retain their draft without inventing a toast contract.

Settings cases observe loaded switch states, optimistic changes in both directions, exact channel requests, preserved unrelated channels, query refresh and rollback. Controlled public push-hook successes verify the UI contract. Separate real-hook cases reach the authenticated unavailable path and show failure without success or an outbound push operation. A cached device permits exercising the unavailable test-delivery action without claiming registration works. The generic non-Error case controls the public update operation and checks the actual resolved fallback message.

Browser tests hover the disabled push control in the built app with synthetic local sessions and verify each explanation. The tooltip content renders without a tooltip role, so the assertions use its visible text. Unit tests retain disabled-control and no-registration behavior. No styling tokens or raw source strings are asserted.

The first full coverage run found four obsolete import-inventory entries requiring the rewritten inquiry tests to import mocked feature modules. Those entries were removed from the existing inquiry and notification migration guards; the remaining guards stay with issue 103. No new source assertion was added.
