# Notification behavior and accepted product gaps

Implementation for [issue 99](https://github.com/bc-solutions-coder/bcordes/issues/99), based on `1b8ad95`. [dispositions.tsv](dispositions.tsv) maps all 117 original cases to retained or replacement behavior. Ten accepted duplicate or structural declarations were removed or consolidated. The stream, push and badge boundary cases added by issue 90 remain covered.

The notification page requests page 1 with 20 records, preserves returned order, and explicitly describes the loaded list. Filters show N of M loaded notifications, including zero results. Empty copy refers to the loaded list. The inert Load more button and unused page state are removed under the accepted issue 81 decision; complete pagination remains deferred. Tests use full, short and empty responses, all seven type controls, combined unread/type filters, selected IDs and actual SDK requests. Mark all read remains account-wide even while filters and selection are active.

The bell now navigates immediately while the read request is pending. A rejected read displays the accepted failure toast after navigation, leaves unread state intact, and permits a successful later retry. Real query invalidation refreshes both the list and account count. The issue 82 decision supersedes the old ledger's wait-before-navigation proposal. Already-read items navigate without another write. The built-browser scenario checks a distinct destination, pending failure, feedback, unread persistence and retry persistence with an isolated synthetic session.

The replacement tests mount real nested routes, query observers, notification hooks, stream providers and rendered feedback. They observe exact public requests, loaded content, destinations, semantic selection states, pending controls and failure recovery. Cache invalidation is judged by refreshed active queries and preserved unrelated data, without requiring a particular number of invalidation calls.

Stream cases verify retry deadlines and budgets, open timeouts, visibility recovery, named reconnect requests and leader/follower delivery. Two mounted providers communicate through a controlled browser channel to verify shared leadership and takeover after the leader unmounts. Subscriber cleanup preserves surviving consumers. No dynamic handler-map replacement behavior was introduced.

Push tests control browser and server-operation boundaries while running the real hook. They verify decoded key bytes, subscription credentials, registered-state refresh, permission state and propagated failures. These controlled successes do not claim that production push registration or delivery is available. Actual registered validation and the authenticated unavailable contract remain covered by the preceding issue 98 suite.

Row tests use the real relative-time formatter and test click, Enter, Space, ignored Tab, and selection without row activation. The browser appearance test uses the actual authenticated page and stylesheet. It observes reduced title weight and changed title color/background after reading, waits for CSS transitions, and verifies saved appearance after reload. No source strings or class tokens are asserted.

The first full run exposed one obsolete notification-module import-inventory entry for the rewritten page test. That entry was removed early; the remaining migration guard belongs to issue 103. A standalone appearance fixture was removed during standards review so appearance coverage uses the actual built application. Both required reviews have zero remaining findings.

All 1,190 unit tests and 39 browser tests pass, with no skips or browser retries. Coverage is 97.39% lines, 96.18% statements, 92.35% branches and 96.08% functions. Build, typecheck, lint, formatting, documentation links and diff checks pass. Forty-three deliberate unit defects were caught and restored. Browser checks caught missing failure feedback, navigation waiting for the read, and missing unread emphasis. The emphasis defect was rerun against the final authenticated-page replacement and failed as intended.

[summary.json](summary.json) records final verification, coverage changes and deliberate-defect evidence. [coverage-summary.json](coverage-summary.json) preserves per-file measurements. Coverage denominators change only where the accepted product changes remove inert state and add handled bell mutations and truthful list copy. No coverage gate or exclusion changes. Browser auth uses local synthetic sessions and the restored production build; these results do not claim remote CI success.
